<!--
Start with why: each project gets its own virtual environment, a folder called .venv with its own packages, so installing something for one project cannot break another. Without it, two projects that need different versions of the same package collide, like different toolbox versions on one MATLAB installation. pip only installs packages, so you manage the environment, the activation and the requirements file yourself. uv covers Python versions, environments, installation and locking in one tool, and it is much faster. You will meet pip in older tutorials, so it helps to know the mapping. Copilot was trained on years of pip examples and will often suggest pip install, so this is a choice you state up front: we use uv, add it with uv add.
-->

# Create a project and <span class="dm-accent">add a package</span>

```powershell
uv init bench-tools
cd bench-tools
uv add matplotlib
uv run python main.py
```

```text
Creating virtual environment at: .venv
Resolved 12 packages in 330ms
Installed 11 packages in 68ms
 + matplotlib==3.11.2
 + numpy==2.5.4
 ...
```

<!--
uv init creates a folder with pyproject.toml, a starter main.py, a .python-version file and a .gitignore. uv add finds a compatible set of versions, creates the project's own .venv if needed, installs, and records the choice. Matplotlib brought ten packages with it, only the first lines are shown, and your versions will differ. Notice that there is no activation step: uv run makes sure the .venv matches the project and runs the command inside it. In VS Code, choose the .venv interpreter once and the play button does the same. To remove a package, run uv remove followed by the name.
-->

# <span class="dm-accent">pyproject.toml</span> declares, <span class="dm-accent">uv.lock</span> pins

```toml
[project]
name = "bench-tools"
requires-python = ">=3.13"
dependencies = [
    "matplotlib>=3.11.2",
]
```

Never edit the lock by hand, run uv lock to refresh it. Commit both files, and not the .venv. A colleague clones the repository, runs uv sync, and gets your environment. The build server on day 3 does the same.
